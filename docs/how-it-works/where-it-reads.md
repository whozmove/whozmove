# Where it reads from

What the panel shows, and where each part of it comes from on your Mac. How the pieces fit together is in the
[overview](overview.md).

| Shows | Comes from |
|---|---|
| Running sessions and status | `~/.claude/sessions/<pid>.json`, Claude Code's live session registry |
| Claude Desktop conversations, running or not | `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json` |
| Terminal sessions that have ended | `~/Library/Application Support/Whozmove/conversations/<id>.json`, which Whozmove writes while each runs (its folder, name, terminal, transcript and when it last moved; no prompts or replies), listed for 3 days while Claude Code still has its transcript; a click runs `claude --resume <id>` in a new tab there |
| What's found in each transcript | each listed session's transcript, `~/.claude/projects/<folder>/<id>.jsonl`, and its sub-agents' records beside it, read every 10 seconds from where the last read stopped (its PRs, edits, writings, context, mode, topic and what it used today); what was found, and where each file was read to, kept in `~/Library/Application Support/Whozmove/reads/<id>.json` (yours only: 600), so a start reads only what's new. One kept by another version of Whozmove, or whose files are other files now, shorter, or not the same up to where it read, is read from its start; a kept read goes once its transcript has, or its session hasn't been listed for 3 days |
| Conversation open in Claude | `setFocusedSession` lines in Claude's `main.log` (instant), else the newest `lastFocusedAt` |
| Session in the Ghostty tab you're looking at | Ghostty's Apple events, once a second while it's in front: the terminals in its front window's selected tab (and the one with the keyboard, when the tab is split), matched to sessions by their folder and tab title, the way a click finds a session's tab. While that can't tell which session it is, the mark stays where it was |
| Session in the iTerm2 tab you're looking at | iTerm2's Apple events, once a second while it's in front: the terminal devices (ttys) of the sessions in its current window's current tab (and of the one with the keyboard, when the tab is split), matched to each session's own, the one iTerm2 gave it, while its `claude` is in its terminal's foreground, the way a click finds a session's tab. A session is iTerm2's when iTerm2, or the server it runs its sessions under (`iTermServer-…`, which keeps them running when iTerm2 quits or crashes), is up its process tree |
| Last prompt / reply / notice | `~/Library/Application Support/Whozmove/sessions/<id>.json`, written by the hook (the folder is yours only: 700) |
| Live line | the same file: the hook describes each tool call as it starts (a command's own description, the file, the query, …) |
| Read, unread, quiet | Unread: a reply (from the hook) you haven't read, however long ago: not opened here since, nor looked at since in Claude, Ghostty or iTerm2 (on it for 2 seconds or more with that app in front, while the screen is awake and unlocked and the keyboard or mouse was used in the last 5 minutes; and Claude's own `lastFocusedAt`), with nothing written to it since. Read: a reply you've read. Quiet: no reply yet, or one you've read with nothing since for a day, the transcript's newest message and the last time you were on it included |
| Order | newest first: your last message, Claude's last reply, when a request came, else the transcript's newest message; a working session by your message, not its steps; a compaction, the summary it leaves included, doesn't count; idle ones below the rest, newest first there too |
| Permission requests | asked by the permission hook over a line of its own to the panel's socket, `~/Library/Application Support/Whozmove/hook.sock`, only you able to connect: the hook checks the panel's own process is at the other end, the panel checks the hook runs in the session it names, and your answer goes back down that line only, as does a hold each second while you're answering it, so it waits. For a session you told not to wait on you, `dont-wait/<id>.json` (since when), which the hook reads. A session started before Whozmove's update leaves its request in `asks/<id>.json` instead, which the panel shows but doesn't answer |
| Branch and worktree | the session folder's `.git`, read directly (no `git` process) |
| Changing model, effort, mode | Ghostty's AppleScript (`input text`, `send key`, `perform action "text:\x13"` for Ctrl+S); iTerm2's Python API while it's on (`send_text` with `suppress_broadcast`, over its Unix socket in `~/Library/Application Support/iTerm2/private`, opened with a one-time cookie from its AppleScript `request cookie and key`), else its AppleScript (`write text … newline no`), each key as the characters it sends (Return, Backspace, Ctrl+S, and Esc `[Z` for Shift+Tab), into the session found by its own terminal device (tty), and through AppleScript only while it's alone in its window, which the same script checks right before typing; Claude Desktop's message box ("Prompt") and Submit button via the Accessibility API; the result from the transcript's `<local-command-stdout>` or Claude's conversation file |
| PRs | `pr-link` entries in the session transcript; open/merged state from `gh pr view`, and a branch's own PR only once the branch is on one of the repo's remotes (`refs/remotes/<remote>/<branch>`, or an upstream there), and never for the repo's default branch |
| Which checkouts changed | macOS's file system events (FSEvents) for each listed checkout's folder, its own git folder and its repo's shared one: git runs again only for a checkout something may have changed in (a branch that moved, only for the checkouts on it, or every one of the repo's when it's the base branch, kept only on this Mac), and every half hour or so anyway |
| The next steps | `git status` (which files are staged, partly staged or not, and how far the branch is ahead of its upstream), and per checkout its base branch (`origin/HEAD`'s, else `main` or `master`) and `git rev-list --count` from there; for Create PR's card, the branches on GitHub as this Mac last fetched them (`git for-each-ref refs/remotes/origin`); the PRs from `gh` |
| What isn't committed | per checkout, once what changed there (as macOS tells it) settles: 2 seconds after the latest change, or 10 seconds after the first while it keeps changing, `git diff` from the last commit, `git diff` alone (not staged), `git diff --cached` (staged) and new files; while there are commits not on GitHub yet, `git log` and `git show` for each; and the edits each session's transcript records (Edit, MultiEdit and Write, with the lines each put in and took out; what Claude Code recorded each shell command changed), with `bashEditDiffEnabled` in the machine's, the project's and your Claude Code settings, which each changed line is matched with |
| Deploy | each project's command, which you confirm in the panel, with a fingerprint (SHA-256) of the scripts, Makefiles and files it runs, and each folder's last deploy, in `~/Library/Application Support/Whozmove/deploy.json`; the port each checkout's build gets, in `ports.json`; which ports a run it started listens on, and its processes, read from macOS while it runs and noted beside it in `deploys/`; each run's log, exit status and whether you stopped it in `deploys/`, and which session asked for it, if one did; suggestions from the project's own files; when an agent last edited files or built, from the hook (`editedAt`, `builtAt`) |
| What a session may do | the switches you turn on at the foot of a session's mode menu (Don't Wait on Me, Let It Deploy), in `~/Library/Application Support/Whozmove/allowed/<id>.json`, and for each, when, and for Let It Deploy the session's process and the command it was turned on for; May Send Back Plans, May Answer Questions and May Approve Plans on only in the panel's memory, kept for the folder you ticked them in, with that folder, the switch and when a session there last held it (never the session) also in `ticked.json` there, which only offers them back after a restart or a Quit, and lets them lapse after 7 days unused; each new session that holds them, by its terminal app and when its process started, in `panel.log`; which session in that folder holds them, by its process as macOS reports it (the folder it works in, its program's signature, the process that started it, the other processes of yours working in that folder); who's on the team, from the team file (`team/team.json`), which the team board also shows whole, by goal, and which project each session is in, from its checkout's `.git`; a session asks the panel through `ask.sock` there, which only you can connect to, and the panel finds which session asks from the process that connects (macOS's `LOCAL_PEERPID`, up to its session in Claude Code's `~/.claude/sessions/<pid>.json`), which counts only when macOS says that process runs Claude Code's build signed by Anthropic (the copy of its signature macOS keeps while it runs), and the folder macOS says it works in |
| Tasks a session hands you | what a session sends with `ask-panel.sh task` through `ask.sock` (the panel finds which session from the process that connects, as for every ask), checked and kept with your answers in `~/Library/Application Support/Whozmove/one-task/<session>/record.json`, until that session's process ends or its row goes |
| The running build | `build.json`, which `build.sh` writes inside the app |
| A team's groups | `~/Library/Application Support/Whozmove/team/team.json`, which a session leading a team of other sessions writes ([The team file](../reference/team.md)): looked at no more than twice a second, read again only when it has changed, and never written by Whozmove; read only while Working on Whozmove ▸ Show Teams is ticked |
| Spotify quieter while you talk | which app is recording from a microphone, from macOS's CoreAudio (its input devices and, from macOS 14, the processes using them), listened to only while Spotify going quieter is on (Spotify's page on the panel's back): never the sound, and no microphone permission is needed |
| Now playing | what Spotify tells the whole Mac each time the song or its state changes (`com.spotify.client.PlaybackStateChanged`); the cover and the controls through Apple events to Spotify, only while it's running; Spotify is opened only when you press its token's Play |
| Lyrics | once you've said yes, LRCLIB (`lrclib.net/api/get`, then `/api/search`), asked about each song once it has played a moment, one request at a time, with its name, artist, album and length, then without the album, with its name tidied of what Spotify adds to say which version it is, and by its name and artist (only that, for a song over an hour); asked again when LRCLIB is busy, never sooner than it says; what it finds is kept in `~/Library/Application Support/Whozmove/lyrics/`, for the last 1,000 songs (a song without timed lyrics for a week, then it's asked about again); and while a song's lines follow it, where it is, asked of Spotify every 5 seconds |
| Plan usage | Claude Code itself: every 3 minutes while a session works or the card is out (every 10 otherwise, and just after a reset; never while you're away from the Mac) Whozmove runs `claude` for a second, with nothing of yours loaded and nothing saved (`--safe-mode --no-session-persistence`), and asks it what its own `/usage` shows (its `get_usage` request); Claude Code signs in and asks Anthropic. When it has no plan to report, `claude auth status` says whether it's signed in. The last numbers it found, each window's percent and reset and when they were checked, nothing else, are kept in `usage-last.json` in Whozmove's folder, so a script of yours can follow your pace without asking again |
| Asked without interrupting | only when you press Ask Without Interrupting in a session's side chat: Whozmove runs that session's own `claude`, in its folder, as a copy of its conversation that's never saved (`--resume <id> --fork-session --no-session-persistence`), kept open for follow-ups until 5 minutes after its last answer, or until the session moves on, ends or compacts; a fresh copy is told your earlier side questions and their answers. It reads none of Claude Code's settings files, so it starts no MCP server, plugin or hook of yours, and before every tool the one hook it's given runs Whozmove itself (`--helper-aside-check`), which lets it only read the project's files in the session's folder (never git's own folder, a file where keys are kept, or a file git ignores, asked of `git check-ignore`) and, when that folder is the top of a git checkout, run git's status, log, diff and show there, with git kept from going online, running hooks or an external diff, or writing its index; anything else, or a check that fails, is refused, and it changes nothing. Claude Code sends that conversation, what the copy reads and your question to Anthropic, as the session itself does, and the answer comes back over its output. The questions and answers are kept in memory only; `panel.log` notes how many tokens it read from the cache and fresh, never the words |
| Disk space | macOS's own count of your disk's free space and size, as Finder shows it, read every minute; a sample each hour kept for two weeks in `~/Library/Application Support/Whozmove/storage/disk.json`, to say how fast it's filling. No folder is opened |
| Clean up | once Storage is on, what's on the map of your disk, and what the tools say, asked when you open it, as Whozmove starts, and after the usual places or a new map are measured (for what the line says Clean up would clean): `brew`, `docker system df` and `xcrun simctl list devices unavailable`, found where your terminal finds them; and `git worktree list`, `git status` and `git merge-base` in the repos your sessions are in. When you press Clean Up's Confirm, only the commands it showed you run, with nothing of Whozmove's environment but your PATH and home, for 10 minutes at most |
| The map of your disk | once Storage is on: your home folder, Applications and the folders every account shares, measured on this Mac (the space each thing takes, read folder by folder), and what macOS says of the disk as a whole; folders macOS protects only with Full Disk Access, and cloud folders never. What it found is kept in `storage/map.json` there, readable by you alone, until you turn Storage off. `git status` and `git check-ignore` in the checkouts it shows, to say what can't go |
| Sessions, on the panel's back | while the panel is turned over (from any page: it's ready by the time you open Sessions on a terminal's page or Claude's), never before you first turn it: every conversation Claude Code keeps (`~/.claude/projects/*/<id>.jsonl`: its folder, its title and when it last moved, read again only when a file changes), where it ran from Whozmove's `conversations/<id>.json`, which ones Claude Desktop keeps from its conversation files (whether its sessions are tracked or not; never what they say), and the running sessions as the list has them; where the ones you moved went, in `~/Library/Application Support/Whozmove/trashed/<id>.json` (yours only: 600, in a 700 folder), until nothing of it is left in the Trash, read at launch and every few seconds too, to give a file Finder put back under the name the Trash gave it its own name again |
| New conversations | in Ghostty or iTerm2, a new tab running `claude --session-id <id>` (an id the panel chooses, so the conversation's row is known from the start), with your words read from a file in Whozmove's folder rather than typed (in iTerm2, the tab's own program, through `create tab with default profile command`, is your shell running a file of commands in your temporary folder, which removes itself as it runs, so nothing is typed into the tab for Broadcast Input to copy, and iTerm2 is given only plain words; with zsh, a Claude paused there with Ctrl+Z comes straight back, as only that shell could bring it back); in Claude Desktop, its `claude://code/new?q=…` link (without `folder=`, which Claude loses), then the environment its button beside Send names, the recent environments its page lists (which is which folder from its `ccd-session-presets.json`, only read) and its Send button via the Accessibility API (on its older screen, its folder button and its folder list's Recent folders, by path), and which conversation it started and where from the `LocalSessions.start:` and `Starting local session <id> in <folder>` lines in its `main.log`; whether Claude may work in the folder, from `projects[<folder>].hasTrustDialogAccepted` in Claude Code's `~/.claude.json` |

What the panel knows about each session, field by field, is in [Rows](../reference/rows.md).
