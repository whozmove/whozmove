# Storage

How full your disk is, what fills it, and what comes back on its own. When it's running low, a line shows above your
sessions: what's left, and how soon it's full at this week's pace, or that builds and sessions may fail once it's nearly
out. Pressed, the line opens Clean up beside the list; while Storage is off, that press is the yes that turns it on, and
Clean up says so, with **Turn Off**. Once Clean up knows what it would clean, the line says how much. **Storage**, among
the **Tools** on the panel's back, leads with what it does: the free space and how fast it's filling, and **Map My
Disk**, which turns the map on and opens Clean up, then **Clean Up** with how much and **Open the Map**; and its
switches, **Know your storage** once it's on, to turn it off, and **Tell me when space runs low**.

**Keys** is Storage's third part: the keys left where they shouldn't be on this Mac. It looks by itself, from the first
launch, a moment after the app starts and once a day after, with no switch: in the projects your sessions are in (a key
in a commit not pushed yet, already pushed, not committed yet, in a new file git would add, or in a remote's address),
in what Claude Code keeps of your conversations and reads as its instructions (what you sent, what its tools read, its
replies, its CLAUDE.md files, memory, skills and the rest, each opened at the key's line, the history of your messages,
long pastes and copies of the files it edited, each tied to its conversation and project, as the agent says, and a
copy named by the file it copies, opened at the key's line there while that file still holds it, else an earlier
copy:
AgentRecords), in what Codex, Gemini CLI and Aider keep of yours, in Whozmove's own record of your last message (where
it masks a key at once), in your shell history, in your shell's settings (the files it reads as it starts: ~/.zshrc,
~/.bashrc and the rest), in credential files and SSH keys other accounts can read (who can read them, never what's in
them, but for whether Docker's holds a sign-in at all) and, with Full Disk Access, in Downloads and in projects in
Desktop and Documents. Each key is kept once, under the most exposed place it's in, with every place it's in, as the
part every key of its kind starts with and its last 4 characters, never more; with the key, Replace it at its provider
(first for one that has left the Mac) and Not a Key; with each place, what can be done there: Open at the line; Show in
Finder for a file with no line; for a credential file, Make it yours only; Move to Trash only for a file that's nothing
but the key (a small key file in Downloads: a private key, a service's credentials, a .env), since any other file holds
more than the key; or, for Claude Code's records, Open the Conversation (while its row is listed) and Copy Clear-Up
Command (the agent's own command that clears what it keeps of that project, `claude purge <folder>`, put on the
clipboard for you to run). Each key also says how soon it needs you (now, when it has left the Mac or is about to; soon,
when it's only on this Mac, or a sign-in token past its own end date; or not at all, when it's most likely made up for a
test: in a project only in its tests' or examples' files, else only in an agent's records, and of a kind with no
provider; when, of such a kind, the conversation it's in calls it made up beside it (a sample, made up, fake, a dummy, a
placeholder, not real, a test's key), a word not denied (not, never, instead of…) nor beside "real", and it's nowhere
but in conversations and tests' files; or most likely an id: a UUID set as no name or one that says nothing secret, as a
lookup's `key`, never a service's key such as HEROKU_API_KEY; or what a Spotify address names), and how likely it is to
be real, worked out on this Mac without asking anyone. Made up by an agent, whatever its shape but one its provider's
checksum proves (GitHub's): in every record it's in, the agent's own words (its command, a file it wrote, its prompt to
a sub-agent) are where it first appears, before any picture or document in that record (what it writes after one may
have been read off it), and it's nowhere else, never in a message you sent, in what an agent reads as its instructions,
or in a file of yours; a compaction's summary is never where anything first appears. A copy cut short (16 characters at
least, the start of a whole key found in the same session, of a kind with no provider or the whole key's own) is that
key, and a value a session also names as a Spotify id is an id in that session, unless it's set as a name that says it's
secret, both told in memory while a look reads and never kept. What can't be a key isn't listed: a run inside a longer
one of base64 (a picture's data, an AI reply's signature); a GitHub token whose checksum fails (its last 6 characters),
or that's too short or too long; a placeholder that counts up (1234567890, abcdefgh); a private key's header with no key
after it (in a test's words, a note about keys); and, of a kind with no provider, a word (under 8 characters, letters
only and under 12, as a long passphrase is a password, or words joined by dashes or underscores), a sentence a match ran
into (two words or more, of letters only, commas between them and bracketed ones among them, maybe ending as a sentence
does; a password with a digit or a sign in it counts, whatever it ends with), a variable's name ($API_KEY, ${API_KEY},
%API_KEY%, R2_SECRET_KEY, process.env.API_KEY, a constant in capitals ending in KEY or KEYS, a user given to curl -u as
"$API_KEY:", what -u is given judged and never the address before it, but not a password that only starts with a $) or a
hash (only hex digits, as long as an MD5's, a SHA-1's or a SHA-256's, a path's last part tested on its own, set as no
name that says key, token, secret, auth, pass or credential: a file's name says none, and a service's key in hex is set
as one; never a hook's address, which often carries its secret as its last part). A key's last 4 characters are its own,
a record's JSON escapes undone. Each text Keys reads from a record is matched on its own, never run into the next. Where
it couldn't look, it says why: Full Disk Access to allow, Apple's developer tools to install, or a copy of Whozmove
without a working Betterleaks, with the way to get it again (the install module's: the command that installs it again,
for a copy Homebrew installed, else the page it comes from). It looks again by itself once what it waited for is there,
and as the app starts after it couldn't look. The line above the list speaks only for the keys that have left the Mac or
are about to: how many, and where, and opens the **Keys** tab beside Map and Clean up (one Storage line at a time: the
disk nearly out, then keys, then the disk low, then the map ready; its × puts away the keys it spoke for, until another
leaves). The tab opens whether the map is on or not. It shows each key once, in **Do now** or **When you can**: its dot,
what it is (with what its line says it's set as or for), where it is in one sentence (a file in every copy of a project,
and its commits, said together), whether it looks real and why, **Show Where**, and its one fix, its best, with a ⌄ for
the rest (a menu: Open at the Line, once for each file of a project, Replace, Open the Conversation, Copy Clear-Up
Command, Mark Replaced for any key but a credential file's, Move to Trash for a file that's nothing but the key, Not a
Key). Show Where lists its places, a project's file once with its lines, copies and commits, each with what to do there
(**Open at the Line**, **Open the Conversation** or **Show in Finder**, on its main copy), else what to do about it in a
few words. Move to Trash, picked from the ⌄, asks once on the file's line; it's never a key's first fix. The keys most
likely made up for a test, and ids, aren't counted, and wait folded at the foot, with Not a Key first; under them, the
keys marked replaced or not a key, folded until pressed, each with **Undo**. Under the list, one thing at a time: what
it couldn't look in and the way to it, or what the last press said.

Storage opens beside the list, on Clean up first. **Map**: rings round the folder you're in, what's in it beside them,
biggest first, with **＋** to collect anything that can go (or why it can't; inside a collected folder, it takes a part
back out), and what's collected under them until **Move to Trash**, which asks once; while it measures, how far it has
got against what's in use. **Clean up**: what comes back on its own, in groups (Xcode's built files, your tools' caches,
space your tools clean up with their own command, models, built files in your projects, and worktrees you're done with),
each ticked or not, or why it can't go, until **Clean Up** with how much, which asks once. Before the first map, it
lists the usual places in a few seconds, as they're measured first; projects' built files and worktrees, which need the
map, join at the list's foot, unticked, once it's done. While it measures, you can close the map: the line says when
it's ready. Full Disk Access comes up only on the map's rows it couldn't look inside for want of it (and what isn't
counted, which holds them), with **Allow Access**.

## Its pieces

- `app/StorageModule.m`: its face for the core (contracts/Module.h): the disk looked at every minute once the app has
  started, the page told what the line says (with what Clean up would clean, worked out again once the usual places or
  a new map are measured), the line's ×; Storage among the tools on the panel's back (its card, with Map My Disk, or
  Clean Up and Open the Map; its switches, kept in the app's
  preferences as `storageOn` and `storageWarn`); the map measured once Storage is on (an hour old, it's measured
  again as the map opens or Storage is turned on; a day old, as the app starts, as measuring reads the whole disk; and
  whatever its age, once Full Disk Access is allowed or taken back, and after a tool's command has cleaned; the line
  and the card say how old the map is that what Clean up frees comes from, once it's over an hour, kMapFreshFor), told the folders agents are at work in (or where a session runs anything in the
  background) and the checkouts the sessions are in (as the rows say), and its presses answered; and the print modes the
  tests check, `--print-disk`, `--print-map`, `--print-cleanup`, `--print-cleanup-usual` and `--print-cleanup-clean`
  (what cleaning does, step by step, moving into a stand-in folder in place of the Trash and running no tool).
- `app/Disk.{h,m}`: the disk's free space and size, read on a queue of its own, as Finder counts them (with the space
  macOS frees by itself when it needs it); a sample each hour, kept for two weeks in `storage/disk.json` in Whozmove's
  folder, with the line's last ×; and what's said from them (`DiskSays`, a plain function): whether it's low, how soon
  it's full at the last week's pace, the line's words, and the card's; and, once Storage is on, the line's second part
  from what Clean up would clean (`DiskLineSub`, a plain function too).
- `app/Scanner.{h,m}`: the map. It measures your home folder, Applications and the folders every account shares, on a
  queue of its own at low priority, reading each folder in bulk (`getattrlistbulk`): the space each thing takes on the
  disk, each file with more names than one counted once, never past the disk it's on, never fetching what's only in
  the cloud. Anything of 1 MB or more is kept (the biggest 100 in a folder); the rest is counted together as its small
  items. A checkout, a folder it can't look inside, and a folder holding either stay on the map whatever their size, so
  they're seen to before the folder they're in can go. With no map yet, it measures Clean up's usual places first (the
  first pass), as a tree of their own numbered below zero, which Clean up lists and cleans until the whole measure is
  done; the measure leaves those folders out and takes the first pass's parts as they are by then, so what was cleaned
  meanwhile is gone, never measured stale. A usual place reached through a link, or on another disk, is left out of the
  first pass, as the whole measure leaves it out; one in a checkout (your home folder, or a folder between it and the
  place, holding a .git) is listed but kept until the whole measure, which asks git about that checkout, takes it in.
  Parts are numbered on from one map to the next, so an id the page had from an earlier map never names a part of this
  one. macOS's own part (every volume on the disk but the one your files are on) and what isn't counted (other accounts, macOS's
  records, Time Machine's snapshots, and what Whozmove can't look inside) come from the disk's own numbers. What it
  found is kept in `storage/map.json`, readable by you alone, so the map opens at once; turning Storage off deletes it.
  It shows the page a folder at a time, three levels down, says what can't go and why, and moves what you collected to
  the Trash, each checked again first: of a folder with parts taken back out of it, what's in it but those, a part at
  a time. `app/ScannerParts.h` is what its files share: a part of the map, a measure, its state and its checks.
- `app/CleanUp.m`: Clean up, found on the map (or before the first map, the first pass): the folders a build or an
  install makes again in each checkout on it, Xcode's built files and its support files for older iOS versions, your
  tools' caches, models, and what the tools say they can free (Homebrew, Docker, Xcode's simulators no longer
  available), asked off the map's queue with your terminal's PATH; and the worktrees you're done with, of the repos the

  moves folders to the Trash, and runs a tool's own command with a time limit. `app/CleanUpFacts.{h,m}`: where each tool
  keeps what it makes again, and the commands that clean what only it should.
- `app/StorageFacts.{h,m}`: what the map relies on about macOS and the tools that keep big stores: the folders macOS
  protects, those kept in the cloud, the folders that stay though what's in them can go, the folders shared by every

## Facts Keys relies on

Checked with Betterleaks 2.0.0-rc.4 (its report a JSON record a line, `--redact`, its fingerprint secret from the
environment, git mode reading history itself) and 1.9.0 (its report one JSON list with each key in it, `dir`,
`--log-opts`, a project's own rules read unless `--config` names others, and its generic rule winning over a kind's own
on `TOKEN=ghp_…`): both count columns in bytes, take in what follows a key in a match, and make the same fingerprint of
a key with the same secret, so a key ignored stays ignored when the version changes. Also with Codex CLI's and Gemini
CLI's documented folders and Aider's history file, as they were then. Where Claude Code keeps its records, and what a
line of each says, is the Claude Code module's (ClaudeCodeFacts.h, Records.m). A release carries only a finished
Betterleaks:
`tools/release.sh` refuses a release line naming a release candidate.

- Betterleaks 1.9.0 misses a key right after an escaped line break in a JSON line, so a record is fed to it as the
  text it holds, its line breaks real again.
- A rule's pattern can match from one text into the next (the private key's runs from a header to the first footer
  after it, whatever comes between), and Betterleaks reports no match of a rule that overlaps another of the same rule.
  So a find whose first and last lines are of different texts is dropped, and the texts it ran over are run again for
  that rule, and after a few rounds of that a text at a time: a key's header cut off at the end of a tool's output
  doesn't hide the key the next record holds, nor do hundreds of them in a row.

## Rules

- The line reads only the disk's free space and size, which needs nothing from macOS: no folder is opened. The map
  measures only once Storage is on: turned on only by a press, Map My Disk or the low-disk line's, and where that opens
  it says so, with Turn Off right there.
- Nothing makes macOS ask you anything: a folder macOS protects is opened only with Full Disk Access, one kept in the
  cloud (iCloud Drive, an app's File Provider folder) never is, nor is anything only in the cloud fetched to be
  measured, and each shows as one it can't look inside. Full Disk Access is asked for only on the map's rows it couldn't
  look inside for want of it, and what isn't counted: never on Storage's page or across the map. Once Allow Access has
  been pressed, those rows say what to do if macOS hasn't listed Whozmove.
- git is asked about every checkout the map finds, wherever it is, so it's never let run a program that checkout's own
  settings name (`core.fsmonitor`). It's only ever the developer tools' own git (RunGit), and xcrun is asked about
  simulators only once Apple's developer tools are there: /usr/bin/git and xcrun offer to install them when they
  aren't. Until then the map's checkouts keep all they hold, saying why, with **Install**, and Clean up offers no
  worktree, saying why the same way; once they're in, git is asked again and the page asks for what it shows.
- Low is under 25 GB free, or under 50 GB and full within a week; under 5 GB, it says builds and sessions may fail.
